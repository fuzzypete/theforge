# Runtime Artifacts Under `.forge`

## Problem

The project currently treats `handoff.yaml` as a runtime gate artifact, but
it still lives at the worktree root and is tracked in git.

This creates three sources of friction:

### P1: Runtime artifacts show up as meaningful git dirt

When the gate rewrites `handoff.yaml`, a finished worktree appears dirty even
if no source files changed. This makes branch/worktree pruning noisy and causes
operators to inspect meaningless diffs.

### P2: Runtime state is split across root and `.forge/`

The repository already uses `.forge/` for worktrees and audits, but handoff
artifacts still live at the worktree root. Runtime state is therefore spread
across two conventions instead of one.

### P3: Tracked generated files blur source of truth

`handoff.yaml` is generated by the gate and re-generated across iterations. A
tracked generated file encourages commit churn and makes it less clear whether
the file is durable project state or ephemeral run output.

## Goals

- Move handoff runtime artifacts into `<worktree>/.forge/`
- Stop tracking root-level `handoff.yaml`
- Treat runtime artifacts as ignorable for worktree cleanliness / prune checks
- Keep handoff-based gate semantics intact
- Update docs, prompts, and tests to the new path

## Non-Goals

- Switching the default gate mode from handoff-based to exit-code-based
- Redesigning the handoff schema
- Moving user-authored specs, code, or config into `.forge/`
- Reworking long-term audit storage beyond aligning paths where necessary

## Design

### 1. New handoff path

Change the default handoff artifact path from:

```yaml
handoff_file: "handoff.yaml"
```

to:

```yaml
handoff_file: ".forge/handoff.yaml"
```

This is relative to the active workspace/worktree root, so each worktree keeps
its own isolated handoff artifact under its local `.forge/` directory.

### 2. Gate commands create the `.forge/` directory

Any default gate command or example command that writes the handoff must ensure
the parent directory exists first.

Examples:

- `forge.yaml` self-hosting config
- `make gate`
- README examples that show handoff-based validation

The default command should create `.forge/` before writing the handoff file.

### 3. Coordinator reads and cleans up `.forge/handoff.yaml`

Coordinator gate handling should continue to:

- delete stale handoff artifacts before running the gate
- parse the gate decision from YAML after the gate runs
- surface handoff content to the reviewer
- extract `dev_notes` if present

Only the default file path changes. Behavior should remain otherwise
unchanged.

### 4. Runtime artifacts do not count as meaningful dirt

Worktree cleanliness checks should ignore runtime artifacts under `.forge/`.
This matters for:

- post-gate clean-worktree validation
- prune decisions
- operator inspection of whether a worktree has meaningful uncommitted changes

During migration, legacy root-level `handoff.yaml` and `forge_audit.yaml`
should also be ignored if they are present as generated leftovers.

### 5. Stop tracking root-level handoff artifacts

Remove `handoff.yaml` from the git index and ensure runtime artifact paths are
ignored instead of committed.

`.gitignore` already ignores `.forge/`, so the primary cleanup is removing the
tracked root-level handoff artifact and any docs/examples that normalize it as
a root file.

## Prune Policy

A worktree is considered prunable when all of the following are true:

1. Its branch is fully merged into `main`
2. It has no meaningful tracked or untracked changes
3. Remaining changes are limited to runtime artifacts only

For prune purposes, runtime artifacts include:

- `.forge/**`
- legacy root `handoff.yaml`
- legacy root `forge_audit.yaml`

Branches that are not merged into `main` are never auto-classified as prunable
solely because their diffs are runtime-only.

## Migration

### Preferred approach: clean cut

Update the default path everywhere in one pass and remove tracked
`handoff.yaml` from the repository.

### Optional compatibility window

If needed, the coordinator may temporarily support the legacy root-level
`handoff.yaml` only when `.forge/handoff.yaml` is absent. This fallback is for
migration safety, not a permanent dual-path design.

If compatibility adds too much complexity, skip it and do a clean cut.

## Acceptance Criteria

- [ ] Default validation config uses `.forge/handoff.yaml`
- [ ] Default gate commands create/write `.forge/handoff.yaml`
- [ ] `make gate` writes `.forge/handoff.yaml`
- [ ] Coordinator stale-handoff deletion works with `.forge/handoff.yaml`
- [ ] Gate decision parsing works with `.forge/handoff.yaml`
- [ ] Reviewer handoff/dev-notes flow works with `.forge/handoff.yaml`
- [ ] Root `handoff.yaml` is no longer tracked in git
- [ ] Runtime artifacts under `.forge/` do not count as dirty for cleanliness checks
- [ ] Legacy root `handoff.yaml` / `forge_audit.yaml` are ignored during transition
- [ ] README and config examples show `.forge/handoff.yaml`
- [ ] Existing gate/coordinator tests pass after path updates

## Test Expectations

In `tests/test_coord_gate.py` and `tests/test_coordinator.py`:

- add/update tests so stale handoff cleanup uses `.forge/handoff.yaml`
- update handoff-writing helpers to write `.forge/handoff.yaml`
- verify dirty-worktree filtering ignores `.forge/handoff.yaml`
- verify legacy root-level runtime artifacts can be ignored during migration
- verify dev-notes extraction still works from the new path

## Notes

This spec intentionally keeps the handoff model intact. The change is about
artifact location and git hygiene, not about changing the coordinator's control
flow or weakening schema/process boundaries.
