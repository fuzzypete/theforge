# v0.2.2 bug fixes

Fix three bugs in the current codebase.

## Bug 1: Fuzzy corroboration for review findings (GitHub issue #34)

Two reviewers flagging the same file and line with different wording are treated as
unrelated findings because corroboration uses exact fingerprint matching. They should
be corroborated if they reference the same file + line (within ±3 lines) regardless
of description wording.

Acceptance criteria:
- Two findings at the same file and line (within ±3 lines) are corroborated even if
  their descriptions differ
- Exact-match fingerprinting continues to work for identical findings

## Bug 2: Plan reviewer must not be same model as planner (GitHub issue #130)

If the plan agent and a plan reviewer share the same model, the review is not
independent. This must be detected and rejected at config load time with a clear
error message.

Acceptance criteria:
- `load_config()` raises `ValueError` if any plan_agent_review pool member uses
  the same model as the planner
- Error message names the conflicting model
- Test covers the invalid config case

## Bug 3: API-provider reviewers default to read-only tools

Gemini and DeepSeek reviewers get unrestricted tool access (including `edit_file`,
`write_file`) when `allowed_tools` is not set in forge.yaml. They should default to
read-only: `read_file`, `bash`, `glob`, `grep`, `submit_review`.

Acceptance criteria:
- API-provider profiles with no explicit `allowed_tools` default to
  `("read_file", "bash", "glob", "grep", "submit_review")`
- CLI-provider profiles continue to use their existing defaults
- Test covers an API-provider profile with no `allowed_tools` set
